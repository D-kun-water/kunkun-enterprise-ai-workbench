# 企业制度与合同商务协作四阶段路线

修订：2026-09-19。当前以本地可验证能力为基线，不把计划写成已上线服务。

## 1. 阶段与决策

| 产品阶段 | 解决什么问题 | 已有产物或启动条件 | 完成判断 |
|---|---|---|---|
| 一：制度问答 | 查到依据并完整回答，范围外不猜测 | 已有解析、检索、门控、回答、引用、反馈收集与回归 | 本地技术验收；真实解决率待测 |
| 二：合同商务协作增强 | 让经办人定位关键条款，交接人工核对结果 | 已有 12 类定位、来源位置、备注与版本化文本导出 | 本地机制验收；独立合同集和业务耗时待测 |
| 三：受控试点与交付 | 用授权资料与真实任务证明价值 | 业务负责人、资料依据、验收集；敏感/多人访问前先满足身份、授权、审计要求 | 一个观察周期后作继续、缩减、停止或扩围决定 |
| 四：可复制服务 | 降低重复交付与运维成本 | 至少两次独立交付证明流程、权限共性与共享收益 | 隔离、迁移回滚和单位交付成本有证据 |

阶段一、二是当前主体；三、四为规划。工程采购与合同商务作为重点验证方向，不把现有物流供应商条款套用于工程分包。

## 2. 第一阶段：把可信问答做实

保留混合检索、来源预览、拒答与反馈。优先修复责任主体混淆、复合问题遗漏、限定语丢失、相邻流程污染及虚假拒答。

Prompt 全文纳入版本管理。代码回归、固定召回、真实模型逐题审计分开报告；降级次数不能算作正常生成成功。反馈归因与加入评测集仍由人员完成，不宣称已有工单运营平台。

## 3. 第二阶段：从条款展示走到人工交接

目标用户是商务、采购经办人与法务复核人。当前已实现：

- 独立合同库、上传、预置允许范围与检索前过滤；
- 主体、金额、期限、付款、账户、保险、担保、终止续约、变更签证、质保、验收、违约等 12 类核对；
- 原文页/章节、系统状态、人工待复核/已确认/需补充及备注；
- 导出合同文本哈希和核对记录，保留人工最终判断。

当前不做自动法律结论、自动审批付款、电子签署和跨合同自动风险评级。记录保存在会话中，尚无服务端归档、多人任务指派或审计签名。

下一步用不同格式、不同条款写法的独立授权合同集测遗漏与误报；比较原始人工核对与辅助核对的总耗时，必须包含复核成本。合成测试样本只能证明机制。

## 4. 第三阶段：先安全接入，再观察业务价值

安全不是试点后的可选补丁。只有不涉及敏感资料的可信本机单人验证，才可继续使用当前角色参数。任何多人、远程或敏感资料试点，至少先完成：

1. 授权、有效版本、保留与删除约定；
2. 服务端真实身份、资源权限和检索前过滤；
3. 管理与敏感访问审计、日志脱敏、备份恢复及受控部署；
4. 独立验收题与停止条件。

随后由真实问题确定是否建设文档版本发布、一个连接器或持久化协同流程，不能先列技术清单再寻找理由。

建议首轮验收题覆盖常见、复合、冲突、过期、无答案与越权场景，数量由任务覆盖决定。20–50 条可作为启动工作量估计，不是达到该数量就证明质量合格。

观察指标：

| 指标 | 分母或口径 | 决策用途 |
|---|---|---|
| 问题解决率 | 取得有效结果反馈的问题；另列反馈覆盖率 | 是否真正帮助完成任务 |
| 正常生成/降级/拒答 | 全部有效请求，三类分别计数 | 质量与可用性取舍 |
| 合同遗漏与误报 | 独立人工标注的应提示项及系统提示项 | 是否减轻而非增加复核负担 |
| 核对总耗时 | 同组任务，包含人工复核与返工 | 业务收益 |
| 知识更新与坏例关闭时长 | 同一计时起止标准 | 运营成本 |
| 单解决任务成本 | 模型、运行、复核和维护成本 | 是否值得继续投入 |

当前均没有真实业务基线，不预填提升比例。观察结束必须允许停止或转向，不把继续扩功能视为唯一正确结果。

## 5. 第四阶段：条件满足才共享服务

至少两次独立交付证明需求与权限共性，且共享部署确有交付或运维收益，才进入多租户专项设计。

候选范围包括服务端租户上下文、数据库/对象/索引/缓存/任务/导出隔离、租户生命周期、版本化 API、幂等与限流、可去重用量事件、独立部署迁移与回滚。

门槛：双租户交叉泄漏为零；单租户暂停或超额不破坏其他租户；迁移可核验回滚；收益有实际测量。自动收费、发票和套餐另立需求，不随“平台化”自动加入。

## 6. 当前减法

不继续扩充资讯、人事、财务、ERP 的静态功能；保留已有集成入口，不宣称业务闭环。移除无人调用的重复页面和无引用素材。暂不拆微服务、不搭多智能体、不为潜在客户预建大量连接器。

优先级依据是任务失败和交付风险，而不是页面数量或技术栈数量。产品定义见 [PRD](../PRD.md)，实际结果见 [发布检查](RELEASE_REVIEW.md)。
