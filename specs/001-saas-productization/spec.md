# 企业 AI 工作台服务化路线——需求规格

**功能编号**：`001-saas-productization`
**创建日期**：2026-09-17
**修订日期**：2026-09-19
**状态**：产品交付版，可评审
**定位**：路线规划，不代表下述能力均已实现

## 1. 文档目的

本规格说明如何把当前本地可运行的单租户企业 AI 工作台，逐步演进为可试点、可安全交付、可重复服务多家企业的产品。

路线以制度问答与合同商务协作为主体，优先验证工程采购任务，不扩建通用办公套件。先保证验证环境安全，再证明问题和价值，最后决定是否共享多租户。敏感或多人试点不能先于真实身份、资源授权和必要审计。

## 2. 当前事实边界

| 能力 | 当前状态 | 事实边界 |
|---|---|---|
| 制度解析、混合检索、证据门控、来源引用、依据不足拒答 | 已实现，可本地验证 | 核心闭环 |
| 固定检索评测、回答质量回归、匿名反馈 | 已实现本地路径 | 反馈归因与案例收录是人工流程，无工单流转 |
| 12 类合同核对、原文位置、人工备注和导出 | 已实现本地路径 | 规则提取与会话内复核，无服务端协同归档 |
| AI 前沿资讯页面 | 已实现页面能力 | 辅助展示，不作为核心价值主线 |
| 预置身份切换和角色参数 | 已实现本地验证机制 | 不是登录、单点登录或完整权限系统 |
| 登录、持久化权限、审计、文档版本管理、连接器 | 未实现 | 企业交付阶段规划 |
| 多租户、用量计量、计费、生产级服务承诺 | 未实现或未验证 | 条件满足后再建设 |
| 客户、线上效果、节省工时、续费和收入 | 无真实证据 | 不作成果宣称 |

## 3. 目标用户与核心问题

| 用户 | 核心任务 | 当前价值 |
|---|---|---|
| 普通员工 | 快速找到制度依据和办理要求 | 缩短检索路径，答案可核验 |
| 知识库运营人员 | 发现解析、检索和知识缺口 | 用评测、反馈和坏例推动迭代 |
| 商务、采购经办人及法务 | 核对付款、结算、变更、质保与履约条款 | 原文位置、待确认项及人工交接；提效待测 |
| 企业 IT、HR、合规负责人 | 判断是否值得试点及如何安全接入 | 获得清晰的价值和风险验证口径 |

## 4. 分阶段用户故事

### 用户故事一：形成稳定、可信的产品验证基线（优先级 P0）

作为产品负责人，我希望核心流程可以在本地稳定复现，并能清楚区分已实现、样例数据和后续规划，从而让评审人员快速核验产品判断和验证方法。

**验收场景**：

1. 运行全量自动化测试时，不依赖本机大模型的随机措辞判断固定事实，结果可重复。
2. 运行固定评测时，报告明确案例数、指标口径和限制，不把离线指标称为线上准确率。
3. 验收制度问答、依据不足拒答、来源核验、反馈闭环和合同审阅辅助时，均可说明输入、处理、输出、异常与人工介入点。
4. README、PRD、路线图和本目录文件对“已实现/规划中”的描述一致。

### 用户故事二：完成一个可度量的单租户试点（优先级 P1）

作为试点业务团队的知识负责人，我希望在独立环境中导入已授权的真实或脱敏资料，建立企业自己的验收问题和反馈口径，以判断产品是否解决了真实问题。

**验收场景**：

1. 资料的来源、授权、版本、生效状态和处理结果可追溯。
2. 验收集逐题记录必答事实、禁止出现的无关事实、正确来源和应拒答情况。
3. 试点报告将检索质量、事实完整性、问题解决率、人工转接率和知识运营成本分开呈现。
4. 第一轮试点完成后，根据真实阻塞项决定后续能力，不默认启动多租户。
5. 任何敏感资料、多人或远程访问前先通过身份、授权与审计验收；当前预置角色只允许可信本机验证。

### 用户故事三：安全接入与需求驱动的交付能力（安全前置，扩展 P2）

作为企业管理员和合规负责人，我希望真实用户通过企业身份访问资料，敏感内容在检索前完成权限过滤，关键操作可审计，制度更新可安全发布和回滚。

**验收场景**：

1. 未认证请求不能进入受保护的读取、检索或写入流程。
2. 未授权用户不能获知合同标题、金额、片段、来源或资源是否存在。
3. 权限过滤发生在向量检索、关键词检索、重排和引用生成之前。
4. 文档新版本先完成解析、索引和验收，再切换为有效版本；失败时继续使用上一版本。
5. 身份、授权与必要审计是敏感或多人试点前置条件；版本发布和连接器按任务证据排序。

### 用户故事四：验证可重复交付后再建设共享 SaaS（优先级 P3）

作为平台运营人员，我希望只有在至少两次独立交付证明需求具有共性后，才把租户隔离、版本化接口、用量计量和配额建设为共享平台能力。

**验收场景**：

1. 两个测试租户的文档、索引、问答、反馈、合同、任务和审计均无交叉泄露。
2. 租户身份只能由已验证身份和服务端成员关系产生，不能相信客户端传入的租户或角色参数。
3. 一个租户的失败、超额或暂停不会暴露或破坏其他租户数据。
4. 用量先做到可去重、可追溯、可对账；自动收费必须另立规格。

## 5. 功能需求

- **需-01**：所有材料必须区分“已实现、样例数据、计划功能、真实试点结果、商业假设”。
- **需-02**：核心问答必须保留来源、原文预览、证据不足拒答和模型不可用提示。
- **需-03**：合同能力必须保持“条款检索与审阅辅助”边界，不给出法律结论。
- **需-04**：固定评测必须同时说明案例数量、指标含义和适用范围。
- **需-05**：复合问题验收必须检查每个必答事实，并检查是否混入无关内容。
- **需-06**：反馈不能自动成为训练或评测数据，必须经过人工归因与筛选。
- **需-07**：真实试点资料必须记录授权、脱敏、保留和删除约定。
- **需-08**：文档版本发布必须支持候选验证、有效版本切换和回滚。
- **需-09**：真实数据环境必须使用服务端身份和权限，不能相信客户端预置角色参数。
- **需-10**：敏感资料必须在检索前过滤，未授权与不存在资源对外表现一致。
- **需-11**：关键管理和敏感访问操作必须形成不可由普通用户修改的审计记录。
- **需-12**：连接器必须由真实试点需求触发，并具备重试、幂等、失败回退和权限映射。
- **需-13**：共享多租户必须覆盖数据库、对象、索引、缓存、任务、导出和删除的隔离。
- **需-14**：自动计费、复杂套餐和生产级服务承诺不属于当前路线交付范围。
- **需-15**：人工核对记录必须带合同文本版本、原文位置和人工状态；默认待复核，不自动批准。
- **需-16**：Prompt、输入模板、异常行为和验收标准必须可评审；正常生成、降级与拒答分别统计。
- **需-17**：公开版本说明融合语料的性质与验证用途，不列具体企业出处，不冒充特定企业现行制度；私有合同原件、密钥、反馈正文与运行索引不得进入公开交付物。

## 6. 非功能要求

- **非功-01 可复现性**：发布前的一键验证不得依赖外网和大模型随机措辞。
- **非功-02 安全性**：任何越权或跨租户数据暴露均为阻断发布的问题。
- **非功-03 可靠性**：文档发布、索引替换和同步失败时保留上一可用状态。
- **非功-04 可观测性**：请求、任务、模型调用和错误可关联，但日志不记录密钥或敏感正文。
- **非功-05 可维护性**：优先保持模块化单体；没有真实规模证据前不拆微服务。
- **非功-06 性能口径**：响应时间、并发和容量目标来自真实试点基线，不从本地验证环境推断。

## 7. 成功标准

- **成功-01**：产品基线的全量测试、固定评测和回答质量回归均可重复通过。
- **成功-02**：10 个手工问题逐题记录必答事实、禁止事实、来源和拒答结果。
- **成功-03**：产品评审材料可完整说明“问题—选择—实现—验证—局限—下一步”。
- **成功-04**：首个真实或内部业务试点有明确的数据授权、验收集和指标定义。
- **成功-05**：进入企业交付阶段前，能指出身份、权限、版本或连接器中的真实阻塞项。
- **成功-06**：进入共享多租户前，至少完成两次独立交付，并证明共享部署有明确的成本或运维收益。
- **成功-07**：任何文档都不把本地验证、内部测试或计划能力写成客户成果或生产能力。

## 8. 阶段门槛

| 阶段 | 进入条件 | 退出条件 |
|---|---|---|
| 产品基线 | 当前代码可运行 | 自动化验证稳定，产品说明和事实边界一致 |
| 单租户试点 | 有已授权资料、业务负责人；敏感/多人环境已通过安全接入 | 得到真实使用、问题解决和运营成本证据 |
| 企业交付 | 安全前置；版本或连接器有实际需要 | 身份、权限、审计通过，真实更新或接入阻塞被关闭 |
| 共享 SaaS | 至少两次独立交付具有共性 | 隔离验证通过，且共享部署收益成立 |

## 9. 明确不做

- 不伪造客户、上线、收入、节省工时或续费结果。
- 不把人事、财务、ERP 场景页描述成已经接通的业务系统。
- 不把预置身份切换描述成完整权限系统。
- 不在真实需求出现前建设复杂微服务、多智能体编排、自动计费或大量连接器。
- 不让 AI 前沿资讯抢占制度问答和合同审阅辅助的核心叙事。
